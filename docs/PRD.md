# PRD: 고교학점제 이수 관리

- 최종 갱신: 2026-10-28
- 대상: 러너스하이 신규 기능 (3팀)
- 상태: 초안. 이 문서가 구현 기준이며, 바뀌는 내용은 이 문서와 docs/PROGRESS.md에 함께 반영한다.

## 1. 개요

학생이 수강 과목과 성적 산출 방식을 등록하고 평가 점수를 입력하면,
졸업 학점 현황과 과목별 이수 위험을 보여주는 기능이다.
이수 위험은 학교의 공식 판정이 아니라 **참고용 예측**이다.

### 배경
- 고교학점제는 2025학년도 고1부터 전면 시행되어 3년간 192학점(교과 174 + 창의적 체험활동 18)을 이수해야 졸업한다.
- 2026학년도부터 선택과목은 출석률 2/3 이상이면 이수이고, 공통과목은 출석률과 학업성취율 40% 이상이 모두 필요하다. 미이수 시 보충과정이 있다.
- 학생이 과목을 직접 선택하는 구조라 "몇 학점을 이수했고, 무엇이 남았고, 어떤 과목이 위험한지" 스스로 파악하기 어렵다.
- 러너스하이는 학습 시간과 태도는 측정하지만 학점·성취 관점은 다루지 않는다.

### 출처와 한계
- 위 제도 내용은 발표 준비 중 확인한 자료 기준이다. 필수 이수 학점 구조 같은 세부는 아직 교육부 원문으로 확인하지 못했다.
- 과목 목록(약 290개)의 출처와 이용 조건은 확인 전이다.

## 2. 범위

### 이번 스프린트 (목요일 발표 기준)
- 큰 틀(학생부 관리) 레이아웃과 메뉴
- 고교학점제 관리 모듈: 학점 현황, 과목 등록, 평가 점수 입력, 이수 위험 표시
- 데모 학생 1명 고정, mock 데이터로 시연 가능할 것

### 이번에 하지 않는 것
- 학교 시스템(NEIS 등) 연계, 학교 출결 자동 수집
- 수행평가, 생기부 관리, 성적 관리 모듈 구현 (빈 페이지만)
- 기존 러너스하이와의 계정/데이터 연결, 로그인과 권한
- 석차 등급 계산, 내신 등급 관리
- 학습 시간과의 연동 (플래너 데이터 확인 후 후속)
- 과목 목록 전체(약 290개) 적재 (시연용 20~30개로 시작)

## 3. 제품 구조

큰 틀 > 모듈 > 기능의 3단계다.

- 큰 틀: 상위 메뉴 하나. 이름은 "학생부 관리"다. 이름은 코드에서 한 곳(상수)에서만 정의한다.
- 모듈
  - 고교학점제 관리: 이번 구현 범위
  - 수행평가: 빈 페이지 (기존 러너스하이에 수행평가 기능이 있어 다시 만들지 않는다)
  - 생기부 관리, 성적 관리: 빈 페이지
- 기능 (고교학점제 관리 안)
  - F1 학점 현황, F2 과목 등록, F3 평가 점수 입력, F4 이수 위험 표시

모듈별로 폴더를 분리한다.
- frontend/src/modules/credit/
- backend 도메인 패키지 credit
- API: /api/student/credit/**
- 테이블 접두사: credit_

## 4. 사용자와 시나리오

- 사용자: 고등학생 (이번 단계는 고1~2)
- 이번 단계는 로그인 없이 **데모 학생 1명(1학년 2학기)**으로 동작한다.

### 시연 시나리오
1. 학점 현황 화면에서 192학점 중 이수 완료 32학점, 수강 중 32학점, 남은 128학점과 경고 배너 "이수 위험 과목 1개 · 주의 1개"를 확인한다.
2. 위험 과목(통합과학2) 행을 눌러 현재 성취율 35%와 "남은 평가에서 평균 45점 이상 받아야 이수 기준(40%)을 넘어요" 안내를 확인한다.
3. 평가 점수를 입력하면 성취율과 상태가 바뀌는 것을 확인한다 (예: 통합과학2에 수행 20%·80점을 추가하면 48% 주의).
4. 신규 과목 등록 모달에서 과목명을 검색하면 교과(군), 유형, 학점이 자동으로 채워지고, 지필 비율을 바꾸면 수행 비율이 자동으로 맞춰지는 것을 보여준다.
5. 과목을 이수 완료로 바꾸면 남은 필수 과목과 학점이 바뀌는 것을 확인한다 (예: 한국사2(3학점)를 이수 완료로 바꾸면 남은 필수 과목 7개 → 6개, 이수 완료 32 → 35학점, 수강 중 32 → 29학점, 남은 학점은 128 그대로).

## 5. 기능 요구사항

우선순위: P0 = 이번 주 반드시, P1 = 시간 되면.

### F0. 큰 틀 레이아웃 (P0)
- 기존 러너스하이처럼 다크 테마와 상단 아이콘 내비게이션을 따른다.
- 큰 틀 안에서 모듈(고교학점제 관리, 수행평가, 생기부 관리, 성적 관리)로 이동한다.
- 수행평가, 생기부 관리, 성적 관리는 "준비 중" 빈 페이지다.
- 인수 기준: 모든 메뉴로 이동할 수 있고 새로고침해도 현재 위치가 유지된다.

### F1. 학점 현황 (P0)
- 진행바: 이수 완료 / 수강 중 / 남은 학점을 한 줄로 보여준다. 기준은 졸업 192학점.
- 교과 174학점과 창의적 체험활동 18학점을 나눠서 표시한다 (예: 교과 29 / 174, 창체 3 / 18).
- 남은 필수 과목 체크리스트: 아직 이수하지 않은 공통과목을 목록으로 보여준다. 각 과목에 상태 배지(수강 중, 주의, 이수 위험)를 붙인다.
- 학기 탭 (1-1 ~ 3-2): 선택한 학기의 수강 과목, 학점, 현재 성취율, 상태를 표로 보여준다.
- 상단 경고 배너: 이수 위험 과목 수와 주의 과목 수를 보여준다. 수강 중인 과목만 센다(이수 완료 과목은 이미 이수했으므로 세지 않는다).
- 인수 기준: 시연 데이터를 넣으면 목업(docs/references)과 같은 숫자가 나온다.
- 남은 학점 = 192 − 이수 완료 − 수강 중. 수강 중인 과목을 모두 이수한다고 가정한 숫자이므로, 화면에 그 점을 작게 표시한다.

### F2. 과목 등록 (P0)
- 신규 과목 등록 모달에서 학기(1-1 ~ 3-2), 과목명, 이수 상태를 입력한다.
- 과목명 검색: 과목 목록에서 고르면 교과(군), 유형(공통/일반선택/진로선택/융합선택), 학점이 자동으로 채워진다.
  - 목록 과목의 유형은 잠기고 바꿀 수 없다. 학점은 학교마다 편성이 다를 수 있어 −/+(또는 직접 입력)로 바꿀 수 있다.
  - 목록에서 "창의적 체험활동"을 고르면 유형은 "창체"로 표시되고, 평가가 없으므로 성적 산출 방식과 성적 표기 방식은 입력하지 않는다(반영 비율 0/0, 표기 방식 없음으로 저장).
- 이수 상태: 수강 중 / 이수 완료. 미래 학기라도 이수 완료로 등록할 수 있다(제한 없음).
- 성적 산출 방식 (학교 평가계획 그대로)
  - 반영 비율: 지필평가 %와 수행평가 %. 합계는 100%. 한쪽을 바꾸면 다른 쪽이 자동으로 맞춰진다. 수행 100%(지필 0%)도 허용한다.
  - 지필 비율은 −/+로 10%씩 바꾸거나 숫자 칸에 0~100 정수를 직접 입력한다. 수행 비율은 항상 100 − 지필이다.
  - 성적 표기 방식 (선택지 세 개): "성취도(A~E)만" / "성취도 + 5등급 함께 표기" / "A·B·C 3단계"(체육·예술 등)
- 목록에 없는 과목은 직접 입력한다 (과목명, 유형, 학점). 직접 입력할 때 고를 수 있는 유형은 공통/일반선택/진로선택/융합선택 4개다(창체는 목록에서 고른다).
- 기본값: 학기는 학점 현황에서 보고 있는 학기 탭, 학점 4, 이수 상태 수강 중, 지필 60 / 수행 40, 성적 표기 방식 "성취도 + 5등급 함께 표기".
- 같은 학기에 같은 과목은 다시 등록할 수 없다. 과목명을 공백과 대소문자를 무시하고 비교하므로, 목록 과목과 같은 이름을 직접 입력해도 중복이다. 다른 학기에는 같은 과목을 등록할 수 있다.
- 성적 표기 방식은 표기 설정일 뿐 이수 위험 계산에는 영향이 없다.
- 인수 기준: 등록한 과목이 학점 현황의 해당 학기 탭과 진행바에 반영된다. 반영 비율 합이 100%가 아니면 등록할 수 없다.

### F2-1. 과목 이수 상태 변경과 삭제 (P0)
- 학점 현황의 과목 행을 누르면 열리는 패널 맨 위, 과목 이름 아래에 버튼을 둔다. 창체 과목 행도 패널이 열린다(창체 패널에는 평가 영역 없이 상태 변경과 삭제만 있다).
- 상태 변경: 수강 중이면 "이수 완료로 변경", 이수 완료면 "수강 중으로 되돌리기". 되돌릴 수 있으므로 확인 단계 없이 바로 적용한다. 이수 위험·주의 과목도 제한 없이 바꿀 수 있다.
- 과목 삭제: 브라우저 확인 창 대신 2단계("이 과목을 삭제할까요? [삭제] [취소]")로 한다. 과목을 지우면 그 과목의 평가도 함께 지운다. 삭제하면 패널이 닫힌다.
- 상태를 바꾸거나 삭제하면 요약(이수 완료/수강 중/남은 학점, 교과/창체 학점), 과목 표, 남은 필수 과목(공통과목: 수강 중이면 포함, 이수 완료면 제외), 경고 배너가 다시 계산된다.
- 이수 완료 과목도 평가 입력·수정·삭제는 그대로 할 수 있다. 상태 배지는 "이수 완료"로 보이고, 이수 위험·주의 표시와 필요 평균 안내는 수강 중인 과목에만 보인다.

### F3. 평가 점수 입력 (P0)
- 과목별로 평가 한 건을 추가한다: 종류(지필/수행), 이름, 반영 비율(%), 만점, 득점, 날짜.
- 득점을 비워 두면 "미입력"이며 계산에서 제외한다.
- 기존 수행평가 화면과 연결하지 않고, 학점 현황의 과목 행에서 직접 입력한다. (수행평가 항목과 연결할 자리로 `taskId`는 선택값으로 비워 둔다.)
- 검증: 득점은 0 이상 만점 이하. 한 종류(지필 또는 수행)의 평가 반영 비율 합은 그 종류의 반영 비율을 넘을 수 없다.
- 인수 기준: 점수를 저장하면 현재 성취율과 상태가 갱신된다.

### F4. 이수 위험 표시 (P0)
- 공통과목: 현재 성취율이 이수 기준(40%) 미만이면 "이수 위험"으로 표시한다.
- 선택과목: 출석률이 이수 기준(2/3, 약 66.7%) 미만이면 "이수 위험"으로 표시한다.
- "주의": 위험은 아니지만 기준에 가까운 상태. 공통과목에서 성취율 40% 이상 50% 미만이다. 기준값은 설정값으로 둔다.
- 입력된 평가가 하나도 없으면 상태는 "미입력"이고 성취율로 위험 판정을 하지 않는다. 단, 출석률 미달은 평가 입력과 관계없이 이수 위험이다.
- 판정 순서 (위에서부터 처음 맞는 것으로 정한다. 성취율은 반올림하기 전 값으로 판정한다):
  1. 출석률이 최소 출석률(66.67%) 미만 → 이수 위험 (모든 과목 유형)
  2. 창체 → 정상 (평가가 없고 출석률로만 판정)
  3. 입력된 평가가 없음 → 미입력
  4. 최소 성취율이 없는 과목(일반선택, 진로선택, 융합선택) → 정상
  5. 성취율 40% 미만 → 이수 위험
  6. 성취율 40% 이상 50% 미만 → 주의
  7. 그 밖 → 정상
- 모든 위험 표시에는 "참고용 예측이며 학교의 공식 판정이 아닙니다"라는 문구를 함께 보여준다.
- (P1) 남은 평가에서 필요한 평균 점수 안내: 6장 계산 규칙 참고. 예: "남은 평가에서 평균 45점 이상 받아야 이수 기준(40%)을 넘어요".
- 인수 기준: 6장의 테스트 케이스가 모두 통과한다.

## 6. 이수 위험 계산 규칙

### 현재 성취율
```
성취율(%) = Σ( 득점 / 만점 × 반영비율 ) ÷ Σ( 입력된 평가의 반영비율 ) × 100
```
- 득점이 NULL인 평가는 분자와 분모에서 모두 제외한다.
- 입력된 평가가 없으면 성취율은 계산하지 않는다(미입력).
- 성취율은 저장하지 않고 항상 계산한다.

### 출석률
```
출석률(%) = ( 총 수업 수 − 결석 수 ) ÷ 총 수업 수 × 100
```
- 총 수업 수를 모르면 이번 단계는 100%로 가정한다 (학교 출결 연계는 후속).

### 이수 기준 (설정값, completion_rule 테이블)
| 과목 유형 | 최소 출석률 | 최소 성취율 |
|---|---|---|
| 공통 | 66.67% | 40% |
| 일반선택, 진로선택, 융합선택 | 66.67% | 없음 |
| 창체 | 66.67% (수업일수 기준) | 없음 |

### 위험 단계 (공통과목 성취율 기준, 설정값)
| 단계 | 성취율 |
|---|---|
| 이수 위험 | 40% 미만 |
| 주의 | 40% 이상 50% 미만 |
| 정상 | 50% 이상 |

출석률 미달과 미입력을 포함한 전체 판정 순서는 5장 F4를 따른다.

### 필요한 평균 점수 (P1)
```
필요 평균(%) = ( 40 × 100 − 현재 성취율 × 입력된 반영비율 합 ) ÷ ( 100 − 입력된 반영비율 합 )
```
- 남은 반영비율이 0이면 안내를 보여주지 않는다.
- 필요 평균이 100%를 넘으면 "남은 평가로는 기준 도달이 어렵습니다"로 표시한다.

### 테스트 케이스
| # | 상황 | 기대 결과 |
|---|---|---|
| 1 | 공통수학2(지필 60%, 수행 40%), 수행평가 1건(반영 20%, 100점 만점) 30점 | 성취율 30%, 이수 위험 |
| 2 | 위 상태에서 수행평가 1건 추가(반영 20%, 100점 만점) 60점 | 성취율 (30×20 + 60×20) ÷ 40 = 45%, 주의 |
| 3 | 평가 입력 없음 | 성취율 계산 안 함, 미입력 |
| 4 | 평가 2건 중 1건 득점 NULL | NULL 건 제외하고 계산 |
| 5 | 입력된 반영비율 합 50%, 현재 성취율 35% | 필요 평균 (4000 − 1750) ÷ 50 = 45% |
| 6 | 선택과목, 출석률 60% | 이수 위험 |
| 7 | 수행 100% 과목(지필 0%), 수행 평가 점수 입력 | 정상 계산 |

## 8. API 요약

상세 명세(요청·응답 예시, 검증 규칙과 오류 문구, 계산 규칙, DB 대응)는 **docs/api-contract.md**가 기준이다. 이 장은 요약이며, 두 문서가 다르면 api-contract.md를 따르고 이 장을 고친다.

- 경로 접두사 /api/student/credit, JSON은 camelCase, ID는 문자열, 날짜는 YYYY-MM-DD.
- 성공: 조회·수정 200, 생성(POST) 201, 삭제 204(본문 없음).
- 오류: 검증 실패 400, 없는 대상 404. 본문은 { "message": ..., "fieldErrors": { 필드: 문구 } } (404는 fieldErrors가 빈 객체).
- 로그인이 없어 데모 학생 1명 고정.

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | /api/student/credit/summary | 학점 현황 요약 (진행바, 교과/창체, 경고 배너) |
| GET | /api/student/credit/courses?gradeYear=1&term=2 | 학기별 수강 과목과 성취율, 상태 |
| GET | /api/student/credit/required-courses | 남은 필수 과목 (이수하지 않은 공통과목) |
| GET | /api/student/credit/catalog?query=공통국어 | 표준 과목 검색 (최대 10개) |
| POST | /api/student/credit/courses | 과목 등록 |
| GET | /api/student/credit/courses/{courseId} | 과목 상세(평가 목록 포함) |
| PATCH | /api/student/credit/courses/{courseId} | 과목 이수 상태 변경 |
| DELETE | /api/student/credit/courses/{courseId} | 과목 삭제 (평가도 함께) |
| POST | /api/student/credit/courses/{courseId}/assessments | 평가 추가 |
| PUT | /api/student/credit/courses/{courseId}/assessments/{assessmentId} | 평가 수정 |
| DELETE | /api/student/credit/courses/{courseId}/assessments/{assessmentId} | 평가 삭제 |

## 9. 시연용 데이터

| 공통수학2 | 공통 | 4 | 46% | 주의 |

| 과학탐구실험2 | 공통 | 1 | 88% | 수강 중 |

## 14. 리스크

- 점수 입력을 학생이 직접 해야 한다: 입력하지 않으면 위험 판정이 되지 않는다. 입력 직후 성취율과 "필요 평균"을 바로 보여줘서 입력할 이유를 만든다. 근본 해결은 학교 시스템 연계이며 이번 범위가 아니다.
- 오판: 현재까지 입력된 평가만으로 계산한 참고용 예측이라, 모든 위험 표시에 "공식 판정 아님" 문구를 둔다.
- 이수 기준 변경: 기준값을 설정 테이블로 둔다.
- 성적은 개인정보다: 이번 단계는 데모 데이터만 쓴다. 실서비스 연결 전에 열람 권한을 정한다.
